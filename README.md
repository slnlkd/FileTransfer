# WPF 文件互传

C# / .NET 10 / WPF 解决方案。服务端共享文件，客户端通过 TCP 多连接分块下载，支持暂停、网络中断和程序重启后的断点续传。使用 Serilog 和 Serilog.Sinks.File 记录结构化滚动日志。

## 项目

| 项目 | 作用 |
| --- | --- |
| Transfer.Server | WPF 服务端：拖拽添加、保存源文件路径、监听 TCP、显示各客户端各文件进度 |
| Transfer.Client | WPF 客户端：连接、选择下载目录、多选文件、并发下载、暂停及继续 |
| Transfer.Core | 协议、TCP 服务、分块下载、断点持久化、SHA-256 校验和远程文件管理核心 |
| RemoteFiles.Server | 新增 WPF 远程文件管理服务端：共享根目录、本地浏览编辑及 EXE 管理 |
| RemoteFiles.Client | 新增 WPF 远程文件管理客户端：目录树、文本/图片查看、上传和 EXE 启停 |
| Transfer.SmokeTests | 使用真实 TCP 的传输与日志集成自检程序，无需测试框架 |
| Transfer.WindowTests | WPF 窗口关闭及两端应用生命周期日志回归验证 |

## 编译和启动

开发环境：Windows 10/11、.NET 10 SDK（或 支持 .NET 10 的 Visual Studio 版本，安装“.NET 桌面开发”工作负载）。打开 `FileTransfer.sln`，分别把服务端与客户端设为启动项目；也可在解决方案属性中配置多个启动项目。

仓库 `global.json` 以 .NET 10 SDK 为最低版本，允许使用更高主版本 SDK，并允许预览版。也可以使用兼容的更高版本 SDK 编译；所有项目目标框架仍为 `net10.0` / `net10.0-windows`，运行时需求仍为 .NET 10。构建工具版本与程序目标框架是两个独立设置。

```powershell
dotnet --list-sdks
dotnet --version
```

如果没有 .NET 10 或更新的 SDK，请安装 .NET 10 SDK x64。仅安装 Runtime / Desktop Runtime 不能编译源码。在 Visual Studio 中使用预览版 SDK 时，若仍无法解析，请在“工具 → 选项”中搜索“预览版 .NET SDK”，启用使用预览版 SDK 并重启；也可以安装 .NET 10 正式版 SDK 并使用支持该 SDK 的 Visual Studio。首次使用更高版本 SDK 面向 .NET 10 构建时，需要本机已有 .NET 10 引用包，或能够从 NuGet 还原缺少的引用包。

PowerShell 中运行：

```powershell
dotnet build .\FileTransfer.sln -c Release
.\Start-Server.ps1
# 在另一个终端启动客户端
.\Start-Client.ps1
```

启动脚本将 SDK 缓存目录设置为当前目录中的 `.local`。也可以直接 `dotnet run --project Transfer.Server` 或 `dotnet run --project Transfer.Client`。

## 使用步骤

1. 服务端点击“启动服务”，默认监听所有 IPv4 网卡的 TCP 9500 端口。
2. 把一个或多个文件拖进服务端窗口，或点击“添加共享文件”。添加时计算 SHA-256，大文件需要等待；共享文件页显示源路径。共享路径会保存，重启后自动恢复并重新计算校验值。
3. 客户端填写服务端 IP 和端口，点击“连接 / 刷新文件”。同一电脑使用 `127.0.0.1`；其他电脑使用服务端显示的局域网 IP。服务端新增文件后需要刷新客户端列表。
4. 点击“选择文件夹”，该目录会被记住。
5. 选择一个或多个文件（Ctrl / Shift 多选），设置每个文件的并发数，点击“下载所选 / 继续”。最多同时下载 3 个文件，其他文件排队；每个文件支持 1～16 个并发连接，默认 4 个。
6. 点击“暂停所选”或“全部暂停”停止传输并保留断点。正常关闭客户端也会等待断点保存。
7. 继续时使用相同下载目录，重新选择文件并点击“下载所选 / 继续”。断网后先恢复网络；服务端重启后先启动监听，客户端刷新并继续。
8. 服务端切换“客户端下载进度”页查看每个文件的进度。每次下载尝试独立显示会话，历史进度行保留。客户端异常退出后，超过 12 秒未收到报告会显示连接中断。

## 断点文件与完整性

例如下载 `资料.zip` 时，目标目录会生成：

```text
资料.zip.<SHA256前16位>.part          二进制临时文件
资料.zip.<SHA256前16位>.part.json     各分块已写入字节数
资料.zip.<SHA256前16位>.part.lock     防止多个进程同时写同一断点
```

分块大小 4 MiB。每累计写入约 1 MiB、分块结束、暂停或异常退出处理时，先将数据刷新到磁盘，再通过临时 JSON 原子替换断点记录。强制结束进程时从最后一次持久化的位置继续，尚未提交断点的数据会重新下载。预分配的 `.part` 长度等于最终文件大小，不能据此判断进度，请使用 JSON 中各分块的偏移。

正常完成后校验整个文件的 SHA-256，成功才改名为原文件名，并删除 `.part.json`。`.lock` 使用独占句柄并在句柄关闭时自动删除；成功后同时清理该任务的 `.part`、`.part.json`、`.part.json.tmp`，只保留正式文件。暂停或失败时保留二进制文件及断点记录用于续传。校验失败会保留二进制文件并把断点重置为零，下次重新下载全部分块。

同名目标文件不会被覆盖。若提示文件已存在，请移走该文件或更换目录，再点击继续；原目录中的完整临时文件可以直接重新校验并改名。源文件内容改变会产生新文件标识，需要在服务端重新添加并刷新客户端，不会将不同版本的分块混用。

请同时保留 `.part` 与 `.part.json`，不要在任务进行时手动修改。缺少其中一个时无法安全续传，将重新下载；JSON 格式或进度不合法时会显示错误，移走对应临时文件后可重下。

## 协议和边界

使用 TCP，命令头为一行 UTF-8 JSON，分块响应紧跟指定长度的二进制数据。`list` 获取清单，`range` 获取字节区间，`progress` 回报客户端已写入字节数。每个请求独立连接，分块连接有 60 秒超时，状态请求有 8 秒超时。失败后保留进度，由用户点击继续；没有后台无限重试。

服务端仅允许请求已共享文件的编号和有效字节范围，不允许客户端指定源文件路径。服务端最多同时发送 64 个分块。不同文件名的相同内容可分别共享。相同文件名的不同源文件应下载到不同目录。

这是可信局域网使用的实现，当前协议没有身份认证和 TLS。跨电脑使用需在服务端允许所选 TCP 端口的入站连接；程序不会自动修改防火墙。服务端读取原文件，没有另外复制一份，因此请保持源文件存在且不变。

配置位于 `%LOCALAPPDATA%\FileTransferDemo`：`server-files.json` 保存共享源路径，`client-folder.txt` 保存下载目录。断点保存在用户选定的下载目录，不在配置目录。

## Serilog 日志与排查

服务端与客户端都已接入 Serilog 4.4.0 / Serilog.Sinks.File 7.0.0。首次从源码构建需要还原 NuGet 包，发布后的程序不需要连接 NuGet 或外网。

窗口顶部的“打开日志目录”可直接定位当前程序日志。默认位置：

- 服务端：`%LOCALAPPDATA%\FileTransferDemo\Logs\Server`
- 客户端：`%LOCALAPPDATA%\FileTransferDemo\Logs\Client`
- `app-20261029.log`：当前级别及以上的完整运行日志。
- `error-20261029.log`：Error、Fatal 日志，包含异常类型、内部异常与完整堆栈。
- `serilog-self-日期-进程号.log`：Serilog 自身的文件写入故障，位于上述默认目录；单文件超过 5 MiB 后保留一份 `.previous` 备份。

日志按本地日期和大小滚动，单文件默认上限 50 MiB，每类日志最多保留 31 个文件（不是保证保留 31 天；同一天可能产生多份）。采用同步、不缓冲的文件写入，正常退出和未处理异常时会执行 CloseAndFlush。强制杀进程、断电和磁盘故障仍可能丢失最后少量日志。

两个发布目录各有 `logging.json`，修改后重启对应程序生效：

```json
{
  "MinimumLevel": "Debug",
  "Directory": "",
  "RetainedFileCountLimit": 31,
  "FileSizeLimitBytes": 52428800
}
```

`Directory` 留空使用默认目录；可填写绝对路径，或相对程序所在目录的路径，例如 `Logs`。可使用 Windows 环境变量，例如 `%LOCALAPPDATA%\\MyTransferLogs`。也可用进程环境变量 `FILETRANSFER_LOG_DIRECTORY` 覆盖目录，优先级高于 JSON。指定目录不可写时会尝试回退默认目录，并记录警告；默认目录也无法写入时启动会显示错误。

默认 `Debug` 已记录每个分块的请求、偏移、长度、耗时、断点持久化和进度报告。`Verbose` 进一步记录每次网络缓冲读写的字节数、磁盘写入位置及协议头长度，用于复现复杂问题；不会记录文件二进制内容。长时间运行希望减少日志量时可设为 `Information`。可用级别：`Verbose`、`Debug`、`Information`、`Warning`、`Error`、`Fatal`。总级别也影响错误日志，例如设为 Fatal 时 Error 不再输出。

| 位置 | 记录内容 |
| --- | --- |
| 应用与窗口 | 启动、版本、机器、PID、线程、窗口创建、用户关闭、重复关闭、退出码、未处理异常 |
| 服务端共享 | 文件选择与拖拽路径、配置恢复/保存、跳过文件、SHA-256、长度、源文件修改时间、添加耗时 |
| TCP | 监听地址/端口、连接建立/结束、本地与远端端点、请求命令、请求编号、非法范围、超时与错误响应 |
| 客户端操作 | 连接/刷新、下载目录、参数校验、多选、并发数、排队、暂停、任务结束与资源释放 |
| 文件传输 | 会话、文件编号、块编号、请求偏移、长度、完成字节、分块耗时及异常 |
| 断点与完成 | 临时文件/锁/JSON 路径、续传字节、断点持久化、异常退出时保存结果、哈希比对、改名、清理 |
| 进度 | 本地状态、向服务端回报、上报失败与恢复、服务端心跳超时 |

排查方法：先按故障时间查 `error-*.log`，再复制该记录中的 `Session` 到客户端与服务端的 `app-*.log` 中查找同一次下载。`FileId` 表示文件版本，`Session` 表示一次下载尝试，`RequestId` 在 TCP 请求中传递，可跨两端定位同一次分块请求；客户端额外记录 `ChunkIndex`，服务端记录 `ConnectionId` 和远端地址。所有日志带毫秒和时区偏移，跨机器按时间比对前请确认系统时钟同步。

日志可能包含真实文件路径、文件名、内网 IP 和机器名，请按内部资料保存。出现问题时保留两端故障时间附近的 app/error 日志及 logging.json；只提供 error 日志可能缺少故障前的操作和分块上下文。

日志验证已并入 `Transfer.SmokeTests`；窗口及应用生命周期日志验证运行：

```powershell
dotnet run --project .\Transfer.WindowTests -c Release
dotnet run --project .\Transfer.WindowTests -c Release -- client
```

## 停止与重新启动服务

服务端启动后可点击“停止服务”。停止过程中禁用启动和停止按钮，关闭 TCP 监听，取消并等待正在处理的连接释放；停止完成后可修改端口并重新启动，共享文件列表及其路径配置会保留。

客户端正在下载时停止服务，客户端会显示中断并保留二进制临时文件与断点记录。服务端重新启动后，客户端等待原下载任务结束，在原目录点击“下载所选 / 继续”即可续传。停止不是删除下载任务，也不会删除客户端已下载的数据。已经完成的文件状态不受影响。

停止请求、活动连接数量、连接取消、停止完成、重新启动及失败异常都写入 Serilog 日志。关闭服务端窗口仍会执行最终资源释放。

## 移除共享文件

在服务端“共享文件”列表右键需要移除的文件，点击“移除所选共享文件（保留源文件）”。支持 Ctrl / Shift 多选后移除。操作会同步保存剩余路径配置，重启服务端不会恢复已移除的记录；源文件保留。客户端点击“连接 / 刷新文件”后获取最新列表（有活动下载时需先暂停并等待任务结束）。

移除后新的文件分块请求会被拒绝；已经开始发送的单个分块可能发送完成，后续请求会提示文件未共享。客户端中断数据按原有断点机制保留，再次共享同一版本文件后可继续下载。移除操作与配置保存结果均写入 Serilog 日志。

## 原文件传输程序：共享文件夹（TCP 9500）

`Transfer.Server` 增加“添加共享文件夹”按钮，也可以把文件夹拖入窗口。共享目录及子目录的文件将出现在原共享列表中，客户端点击“连接 / 刷新文件”会重新扫描共享目录并发现新增、修改及移除的文件。文件夹内使用相对路径显示，避免同名文件混淆；同一层的同名根共享目录和重叠共享根目录不能重复添加。

客户端可选中文件夹点击“下载所选 / 继续”，自动下载其中的全部文件，保留子目录和空目录。也可只选择部分文件下载。原有并发、断点续传、校验及完成清理保持有效。服务端重启恢复文件夹路径；右键移除文件夹会移除其全部共享子项，源目录保留；右键移除目录内单个文件或子目录会保存排除记录，后续刷新及重启不会重新共享该项。

刷新需要扫描并计算新增或变更文件的 SHA-256，大文件目录可能需要等待；正常文件夹扫描跳过链接/重解析点。空目录也会返回目录记录。新旧端的 SharedFile 模型已扩展，请同时更新原来的服务端与客户端。

## 新增独立程序：远程文件管理（TCP 9501）

两个新增项目为 `RemoteFiles.Server` 和 `RemoteFiles.Client`，使用独立端口 9501，和原文件传输程序的端口 9500 分开。四个项目都保持 .NET 10 / WPF，均写入 Serilog 日志。

### 启动和浏览

1. 运行 `RemoteFiles.Server`，点击“选择文件夹”设置共享根目录，点击“启动服务”。根目录和端口会保存，重启后恢复。
2. 服务端本身也有左侧树、右侧文件列表，可在启动服务后查看和修改该目录中的内容。
3. 运行 `RemoteFiles.Client`，填写服务端内网 IP 和 TCP 9501，点击“连接 / 刷新根目录”。IP 与端口会保存。
4. 左侧树包含文件夹和文件，展开目录时加载其子项；选择文件夹更新右侧列表。双击右侧文件夹进入，双击树中或列表中的支持文件打开相应窗口。
5. “刷新当前目录”重新获取该目录；“返回上一级”返回父目录；“连接 / 刷新根目录”重建整个树。

### 文本：txt / log / json

双击文本文件后打开编辑窗口，可以查看、修改，点击“保存到服务端”或按 Ctrl+S 保存。支持 UTF-8（带或不带 BOM）、带 BOM 的 UTF-16 / UTF-32，以及 UTF-8 解码失败后的 GBK。保存时保留识别出的编码；采用 SHA-256 版本检测，编辑期间远程文件变化会拒绝保存并保留编辑内容。临时文件写完后会再次检查目标版本再替换，服务内写操作串行执行。外部程序不受本服务的锁控制，建议暂停持续写入的日志程序后再编辑其日志。

当前完整文本查看/编辑上限为 **1 MiB**，超过上限会显示提示，不会截断文件后保存。JSON 按文本原样编辑，不自动格式化或校验语法。未保存内容关闭时会提示确认。

### 图片：jpg / png

双击图片后获取同一文件夹内的 jpg / png 列表，按 **创建时间从早到晚** 排列，时间相同时按文件名排序。按 **Left / Right** 切换上一张或下一张，也可点击对应按钮；到首尾停止切换，不循环。窗口显示序号、路径和创建时间。

图片按服务端文件的 CreationTimeUtc 排序，在界面显示本地时间。复制或上传可能改变创建时间，因此排序依据是当前服务端文件系统的创建时间。图片预览限 **64 MiB**，显示时按最长约 2400 像素宽度解码以控制内存，不修改原图。浏览期间有新增图片时，关闭并重新打开可刷新图片序列。

### EXE 状态、停止、上传和重新运行

双击 exe 打开程序状态窗口，显示运行状态和 PID，每 3 秒自动刷新。通过完整可执行文件路径匹配进程，同名但位于其他目录的程序不被停止。权限不足无法读取进程路径时显示“状态未知”，不会假定程序未运行。

推荐更新流程：

1. 双击目标 EXE，点击“停止程序”，确认显示未运行。
2. 在浏览器进入 EXE 所在目录，点击“上传文件到当前目录”。支持多选文件；文件已存在时选择覆盖。上传程序所需的依赖 DLL、配置文件等也应选择对应版本一起上传。
3. 上传成功后，在 EXE 状态窗口点击“启动程序”，或点击“重新启动”（执行停止后再启动）。

运行中的 EXE 不允许被上传覆盖。上传通过独立临时文件接收和 SHA-256 校验后才替换目标文件，失败/中断会删除上传临时文件并保留原目标文件；每个文件独立提交，多文件上传不构成整体事务。新文件管理上传暂不支持断点续传；需要分块断点下载请使用原 Transfer 程序。

EXE 在服务端电脑上、以服务端当前 Windows 用户身份运行，工作目录设为 EXE 所在目录，不附加命令行参数。停止当前匹配的进程，不主动停止整个子进程树；不能远程停止管理服务端自身。不执行提权，权限不足将记录异常。停止文件管理服务不会自动停止已启动的业务 EXE。

### 文件操作范围与日志

新服务仅操作选定共享根目录，拒绝绝对路径、目录穿越、链接/重解析点和 NTFS 备用数据流。txt/log/json 提供内容编辑，jpg/png 提供图片查看，exe 提供进程管理；其他类型可以显示和上传，不增加预览、编辑或特殊运行操作。可以在当前目录新建文件夹。

两端默认日志目录分别为 `%LOCALAPPDATA%\FileTransferDemo\Logs\RemoteFiles.Server` 和 `%LOCALAPPDATA%\FileTransferDemo\Logs\RemoteFiles.Client`，沿用 `app-*.log` / `error-*.log` 及 `logging.json`。请求携带 RequestId，可跨两端关联读取、保存、上传、启动、停止及异常。配置文件为 `%LOCALAPPDATA%\FileTransferDemo\remote-server.json` 与 `remote-client.json`。

内网实现没有认证和 TLS，能连接 9501 的客户端具有共享根目录内的读写和 EXE 管理能力，请将服务端共享根目录设置为实际需要管理的目录，并在部署环境按需放行 TCP 9501。跨电脑连接、防火墙、Windows 用户权限与实际业务 EXE 的依赖环境仍需要部署现场验证。

### 文件 / 文件夹压缩、ZIP 下载、删除与进度

`RemoteFiles.Client` 和 `RemoteFiles.Server` 的左侧目录树、右侧文件列表都支持以下右键操作：

1. 右键文件或文件夹 → **添加压缩包**：请求 `RemoteFiles.Server` 生成 ZIP，完成后自动刷新到 ZIP 所在目录。文件夹 ZIP 中包含所选文件夹本身、子目录、空目录和文件，中文名称保留；单文件 ZIP 只包含该文件，例如 `trace.log` 生成 `trace.log.zip`。所有文件类型均支持压缩，原有内容预览类型不变。
2. 右键 ZIP → **下载 ZIP…**：选择本机保存位置，流式接收 ZIP，进行 SHA-256 校验并落盘后才显示完成。本地同名文件存在时拒绝覆盖，请选择新的保存名称。
3. 右键文件夹 → **打包下载文件夹…**：选择本机 ZIP 保存位置，依次执行“服务端压缩 → ZIP 下载 → 本地校验”。下载结果是 ZIP 文件，不自动解压。服务端窗口的本地浏览器也支持相同操作。
4. 右键文件（包含生成的 ZIP）→ **删除服务端文件…**：弹出默认选择“否”的确认框；确认后永久删除服务端磁盘上的该文件并刷新目录。删除 ZIP 不删除原始文件或目录，也不删除已下载的本地 ZIP。文件列表加载后若大小或修改时间已变化，拒绝删除并提示先刷新；运行中或状态未知的 EXE 要先停止。文件夹和共享根目录不提供删除操作，协议也拒绝递归删除。

例如选择 `共享目录/业务日志`，服务端创建 `共享目录/业务日志.zip`；若已存在，依次使用 `业务日志 (1).zip`、`业务日志 (2).zip`。压缩共享根目录时，将 ZIP 放在根目录内部。先生成待压缩清单再创建临时文件，因此不会将本次 ZIP 压入自身；根目录内以前已有的 ZIP 属于正常源文件，会被包含。

客户端底部显示扫描、压缩、计算校验值、下载、完成各阶段。扫描时使用等待动画，压缩百分比按源文件已处理字节计算，下载按 ZIP 已接收字节计算，校验和落盘后显示 100%。服务端下方的“压缩 / 下载进度”表按请求显示路径、阶段和进度，最多保留最近 200 条；发送结束后等待客户端的校验落盘回执，收到后显示“下载完成”。其他客户端请求会新增进度行。

压缩使用 .NET 内置 ZIP 和 128 KiB 缓冲流，不将整个压缩包载入内存。压缩和服务内上传/保存串行执行；源文件被其他程序修改、文件被占用、权限不足或磁盘空间不足时显示错误并记录异常。压缩仅访问共享根目录，拒绝越界和链接路径，不修改源目录。临时 ZIP 成功后才改名为正式 ZIP，失败或服务正常停止时清理临时文件。下载成功或可捕获的失败会清理本次 `.part`；强制结束进程或断电可能留下临时文件。

**此处新增的 ZIP 下载暂不支持断点续传**，连接中断后需重新下载。服务端已完成的 ZIP 保留，可直接再次下载；需要多线程断点下载时使用原 `Transfer.Server` / `Transfer.Client`。大目录压缩与下载单次请求最长 24 小时。上传、文本、图片与 EXE 管理保持原操作方式。

两端 Serilog 记录请求编号、源路径、ZIP 路径、扫描条目数、原始字节数、压缩文件、进度、下载临时文件、SHA-256、提交结果、客户端回执、删除确认或取消、删除文件与失败堆栈，可使用同一 `RequestId` 对照排查。此次更新须同时替换 `RemoteFiles.Server` 和 `RemoteFiles.Client` 的完整发布目录。
